请求头与消息流

口播全流程助手里，浏览器、agent/server.py 和 agent/llm.py 怎么对接： 认证头，以及 run_agent 每一轮在做什么。文字说明见 docs/message-flow.md。

Fig. 1系统拓扑

三个进程内 / 外部角色：浏览器页面、你自己起的 server.py（llm.py 是它内部调用的一个模块，不是独立服务），和 Anthropic 的 API。

这些 header 什么用认证 + 协议版本

anthropic-version
固定写 2023-06-01。这不是你账号的版本，是"请求/响应字段按哪套协议解析"的版本号——锁死它，Anthropic 以后升级接口也不会突然改变你代码里字段的含义。
x-api-key
直连官方 Anthropic API 的标准认证方式，值来自 ANTHROPIC_API_KEY。
Authorization
值是 Bearer $ANTHROPIC_AUTH_TOKEN，用于兼容网关。两个都设置时 bearer 优先。

llm.py 只读 ANTHROPIC_*。env.sh 会在对应的 ANTHROPIC_* 为空时，把旧名 PARALLIGHT_BASE_URL / PARALLIGHT_API_KEY 映射过去。

Fig. 2run_agent 循环

一次用户消息，模型可能不会一步给出答案——它可能先要求"帮我调个工具"。这个循环就是在处理这种来回。

按时间顺序一条消息的完整旅程

  1. 浏览器里敲回车 → fetch('/api/chat', {method:'POST', body:{session, text}})。
  2. server.py 拿这个 session 的历史消息 + 新消息 + 工具 schema，调 llm.py 发给 Anthropic（带上面那些 header）。
  3. 模型要么直接回文本，要么在响应里带 tool_use 块，点名一个已注册的工具（诊断用的 echo 也在其中）。
  4. 有 tool_use 就在 Python 里实际执行对应函数，把返回值（或异常信息）按 tool_use_id 包成 tool_result，塞回消息列表。
  5. 带着更新后的消息列表，回到第 2 步再调一次模型——直到某一轮它只回纯文本，或者凑够 12 轮强制停止。
  6. 上面每一步的动静（吐字、调用了什么工具、工具结果、报错、结束）都实时编码成一帧 SSE，推给浏览器；页面里的 JS 读这个流，把工具调用渲染成 ⚙ name(args)，结果渲染成 ✓ / ✗。
